> [!remark] Basic Question of Message Integrity 
> Bob receives a message $m$ from Alice and wants to convince himself that the message was not modified en-route. We will design a mechanism that lets Alice compute a short message integrity tag $t$ for the message $m$ and send the pair $(m, t)$ to Bob. Upon receipt, Bob checks the tag $t$ and rejects the message if the tag fails to verify. If the tag verifies then Bob is assured that the message was not modified in transmission.

> [!principle]
> Providing message integrity between two communicating parties requires that the sending party has a secret key unknown to the adversary.

## Definition

> [!definition] Message Authentication Code
> A **MAC** system $\mathcal I = (S, V)$ is a pair of efficient algorithms, $S$ and $V$, where $S$ is called a **signing algorithm** and $V$ is called a **verification algorithm**. Algorithm $S$ is used to generate tags and algorithm $V$ is used to verify tags.
> - $S$ is a probabilistic algorithm that is invoked as $t \xleftarrow{R} S(k, m)$, where $k$ is a key, $m$ is a message, and the output $t$ is called a **tag**.
> - $V$ is a deterministic algorithm that is invoked as $r \leftarrow V(k, m, t)$, where $k$ is a key, $m$ is a message, $t$ is a tag, and the output $r$ is either `accept` or `reject`.
> - We require that tags generated by $S$ are always accepted by $V$; that is, the MAC must satisfy the following **correctness property**: for all keys $k$ and all messages $m$, $$P[V(k, m, S(k, m)) = \text{accept}] = 1.$$
> 
> We say that keys lie in some finite **key space** $\mathcal K$, messages lie in a finite **message space** $\mathcal M$, and tags lie in some finite **tag space** $\mathcal T$. We say that $\mathcal I = (S, V)$ is defined over $(\mathcal K, \mathcal M, \mathcal T)$.

> [!definition] Valid tag
> Whenever algorithm $V$ outputs `accept` for some message-tag pair $(m, t)$, we say that $t$ is a **valid tag** for $m$ under key $k$, or that $(m, t)$ is a **valid pair** under $k$.

> [!proposition] Type of MAC
> - **Deterministic MAC system**: Signing algorithm $S$ is deterministic, thus it has **unique tags**: For a given $k$, and a given message $m$, there is a unique valid tag for $m$ under $k$.
> - **Randomized MAC system**: Randomized signing algorithm and output of $S(k, m)$ may be one of many possible valid tags. These systems are not necessary to achieve  security, but they can yield better efficiency/security trade-offs.

> [!definition] Message Authentication Code (Mathematical Details)
> A **MAC** system is a pair of efficient algorithms, $S$ and $V$, along with three families of spaces with system parameterization $P$: $$K = \{\mathcal K_{\lambda, \Lambda}\}_{\lambda, \Lambda}, M = \{\mathcal M_{\lambda, \Lambda}\}_{\lambda, \Lambda}, T = \{\mathcal T_{\lambda, \Lambda}\}_{\lambda, \Lambda}.$$ As usual, $\lambda \in \mathbb Z_{\geq 1}$ is a security parameter and $\Lambda \in \text{Supp}(P(\lambda))$ is a domain parameter. We require that
> 1. $K, M$, and $T$ are efficiently recognizable.
> 2. $K$ is efficiently sampleable.
> 3. Algorithm $S$ is an efficient probabilistic algorithm that on input $\lambda, \Lambda, k, m$, where $\lambda \in \mathbb Z_{\geq 1}, \Lambda \in \text{Supp}(P(\lambda)), k \in \mathcal K_{\lambda, \Lambda},$ and $m \in \mathcal M_{\lambda, \Lambda}$, outputs an element of $\mathcal T_{\lambda, \Lambda}$.
> 4. Algorithm $V$ is an efficient deterministic algorithm that on input $\lambda, \Lambda, k, m, t$, where $\lambda \in \mathbb Z_{\geq 1}, \Lambda \in \text{Supp}(P(\lambda)), k \in \mathcal K_{\lambda, \Lambda}, m \in \mathcal M_{\lambda, \Lambda}$, and $t \in \mathcal T_{\lambda, \Lambda}$, outputs either `accept` or `reject`.

### MAC Security

> [!definition] Parameters
> - $\mathcal I = (S, V)$: a MAC system defined over $(\mathcal K, \mathcal M, \mathcal T)$.
> - $Q$: the maximal number of signing queries.

> [!definition] MAC Security
> ### Scope
> A MAC system $\mathcal I$ and all efficient adversaries.
>
> ---
> ### Condition
> - **Access** — signing queries: $\mathcal A$ sends messages and receives their tags under $k$ (a chosen message attack).
> - **Promise** — none.
> - **Quantifier** — $\forall$ efficient $\mathcal A$; a **$Q$-query MAC adversary** issues at most $Q$ signing queries.
> - **Adaptivity** — each query and the forgery may depend on the earlier answers.
>
> ---
> ### Experiment
> A search game: one branch. `[BS Attack Game 6.1]`
>
> | | challenger $\mathcal C$ | | adversary $\mathcal A$ |
> | --- | --- | --- | --- |
> | 1 | $k \xleftarrow{\$} \mathcal K$ | | |
> | 2 | | $\xleftarrow{\ m_i\ }$ | **Signing queries** (repeated, adaptive, at most $Q$ times): sends $m_i \in \mathcal M$ |
> | | $t_i \leftarrow S(k, m_i)$ | $\xrightarrow{\ t_i\ }$ | |
> | 3 | | $\xleftarrow{\ (m,\, t)\ }$ | outputs a candidate forgery pair $(m, t) \in \mathcal M \times \mathcal T$ |
> | 4 | $r \leftarrow V(k, m, t)$ | | |
>
> **Goal** — $\mathcal A$ wins iff all of:
> - $(m, t) \notin \{(m_1, t_1), (m_2, t_2), \dots\}$: the pair is not among the signed pairs;
> - $r = \text{accept}$: $(m, t)$ is a valid pair under $k$.
>
> ---
> ### Property
> $$\text{MACadv}[\mathcal A, \mathcal I] = \Pr[\mathcal A \text{ wins}].$$
> - **Secure MAC** — a MAC system $\mathcal I$ is secure if $\text{MACadv}[\mathcal A, \mathcal I]$ is negligible for every efficient adversary $\mathcal A$.
>
> It is a *search* game, see [[Security Game]].

> [!remark]
> The pair $(m, t)$ is called an **existential forgery**, and the MAC system that satisfy the secure criteria are said to be **existentially unforgeable under a chosen message attack**.

> [!remark] Notation in the literature
> - `[BS]` has no key-generation algorithm for a MAC: the challenger picks $k \xleftarrow{R} \mathcal K$, written $k \xleftarrow{\$} \mathcal K$ above.
> - `[BS]` states "not among the signed pairs" as a restriction on the pair $\mathcal A$ outputs; here it is a winning condition, which gives the same probability.
> - `⚠️ CLAUDE – verify:` from memory: Katz–Lindell's basic definition (key generation $\mathsf{Gen}$, experiment $\mathsf{Mac\text{-}forge}$) only asks for a new *message*, $m \notin \{m_1, m_2, \dots\}$, and calls the pair condition used here a *strongly secure* MAC.

### MAC Verification Queries

> [!definition] Parameters
> - $\mathcal I = (S, V)$: a MAC system defined over $(\mathcal K, \mathcal M, \mathcal T)$.
> - $Q_s$, $Q_v$: the maximal numbers of signing and verification queries.

> [!definition] MAC Security with Verification Queries
> ### Scope
> A MAC system $\mathcal I$ and all efficient adversaries.
>
> ---
> ### Condition
> - **Access** — signing queries and verification queries, in any order.
> - **Promise** — a verification query is never a previously signed pair: $(\hat m_j, \hat t_j) \notin \{(m_1, t_1), (m_2, t_2), \dots\}$.
> - **Quantifier** — $\forall$ efficient $\mathcal A$ with at most $Q_s$ signing and $Q_v$ verification queries.
> - **Adaptivity** — each query may depend on the earlier answers.
>
> ---
> ### Experiment
> A search game: one branch. `[BS Attack Game 6.2]`
>
> | | challenger $\mathcal C$ | | adversary $\mathcal A$ |
> | --- | --- | --- | --- |
> | 1 | $k \xleftarrow{\$} \mathcal K$ | | |
> | 2 | | $\xleftarrow{\ m_i\ }$ | **Signing queries** (repeated, adaptive, at most $Q_s$ times, interleaved with row 3): sends $m_i \in \mathcal M$ |
> | | $t_i \leftarrow S(k, m_i)$ | $\xrightarrow{\ t_i\ }$ | |
> | 3 | | $\xleftarrow{\ (\hat m_j,\, \hat t_j)\ }$ | **Verification queries** (repeated, adaptive, at most $Q_v$ times): sends $(\hat m_j, \hat t_j) \in \mathcal M \times \mathcal T$ with $(\hat m_j, \hat t_j) \notin \{(m_1, t_1), (m_2, t_2), \dots\}$ |
> | | $r_j \leftarrow V(k, \hat m_j, \hat t_j)$ | $\xrightarrow{\ r_j\ }$ | |
>
> **Goal** — $\mathcal A$ wins iff any of:
> - $r_j = \text{accept}$ for some verification query $j$.
>
> ---
> ### Property
> $$\text{MAC}^{vq}\text{adv}[\mathcal A, \mathcal I] = \Pr[\mathcal A \text{ wins}].$$
> - $\mathcal I$ is **secure in the presence of verification queries** if $\text{MAC}^{vq}\text{adv}[\mathcal A, \mathcal I]$ is negligible for every efficient $\mathcal A$.

> [!theorem]
> If $\mathcal I$ is a secure MAC system, then it is also secure in the presence of verification queries.
> 
> In particular, for every [[#MAC Verification Queries|MAC security with verification queries]] adversary $\mathcal A$ that attacks $\mathcal I$, and which make at most $Q_v$ verification queries and at most $Q_s$ signing queries, there exist a $Q_s$-query [[#MAC Security|MAC security]] adversary $\mathcal B$ that attacks $\mathcal I$, where $\mathcal B$ is an elementary wrapper around $\mathcal A$, such that $$\text{MAC}^{vq}\text{adv}[\mathcal A, \mathcal I] \leq \text{MACadv}[\mathcal B, \mathcal I] \cdot Q_v.$$

### Nonce-based MAC

> [!algorithm] Nonce-based MAC
> A **nonce-based MAC** consists of a pair of **deterministic** algorithm $S$ and $V$ for signing and verifying tags. However, these algorithms take an additional input $n$ called a nonce that lies in a **nonce-space** $\mathcal N$. Algorithm $S$ and $V$ works as follows:
> - $S$ takes as input a key $k \in \mathcal K$, a message $m \in \mathcal M$, and a nonce $n \in \mathcal N$. It outputs a tag $t \in \mathcal T$.
> - $V$ takes as input four values $k, m, t, n$, where $k$ is a key, $m$ is a message, $t$ is a tag, and $n$ is a nonce. It outputs either `accept` or `reject`.
> 
> We say that the nonce-based MAC is defined over $(\mathcal K, \mathcal M, \mathcal T, \mathcal N)$. The MAC must satisfy the following **correctness property**: for all keys $k$, all messages $m$, and all nonces $n \in \mathcal N$: $$V(k, m, S(k, m, n), n) = \text{accept}.$$

> [!definition] Parameters
> - $\mathcal I = (S, V)$: a nonce-based MAC system defined over $(\mathcal K, \mathcal M, \mathcal T, \mathcal N)$.
> - $Q$: the maximal number of signing queries.

> [!definition] Nonce-based MAC Security
> ### Scope
> A nonce-based MAC system $\mathcal I$ and all efficient adversaries.
>
> ---
> ### Condition
> - **Access** — signing queries on a message and a nonce of $\mathcal A$'s choice.
> - **Promise** — the signing nonces are distinct: $n_i \neq n_j$ for all $j < i$. The forgery's nonce may repeat one of them.
> - **Quantifier** — $\forall$ efficient $\mathcal A$.
> - **Adaptivity** — each query, nonce included, and the forgery may depend on the earlier answers.
>
> ---
> ### Experiment
> A search game: one branch. `[BS Attack Game 7.4]`
>
> | | challenger $\mathcal C$ | | adversary $\mathcal A$ |
> | --- | --- | --- | --- |
> | 1 | $k \xleftarrow{\$} \mathcal K$ | | |
> | 2 | | $\xleftarrow{\ m_i,\, n_i\ }$ | **Signing queries** (repeated, adaptive, at most $Q$ times): sends $m_i \in \mathcal M$ and a nonce $n_i \in \mathcal N$ with $n_i \neq n_j$ for all $j < i$ |
> | | $t_i \leftarrow S(k, m_i, n_i)$ | $\xrightarrow{\ t_i\ }$ | |
> | 3 | | $\xleftarrow{\ (m,\, t,\, n)\ }$ | outputs a candidate forgery triple $(m, t, n) \in \mathcal M \times \mathcal T \times \mathcal N$ |
> | 4 | $r \leftarrow V(k, m, t, n)$ | | |
>
> **Goal** — $\mathcal A$ wins iff all of:
> - $(m, t, n) \notin \{(m_1, t_1, n_1), (m_2, t_2, n_2), \dots\}$;
> - $r = \text{accept}$.
>
> ---
> ### Property
> $$\text{nMACadv}[\mathcal A, \mathcal I] = \Pr[\mathcal A \text{ wins}].$$
> - A nonce-based MAC system $\mathcal I$ is **secure** if $\text{nMACadv}[\mathcal A, \mathcal I]$ is negligible for every efficient adversary $\mathcal A$.

> [!remark]
> $S$ is deterministic, so the table writes $t_i \leftarrow S(k, m_i, n_i)$ where the previous version had $t_i \xleftarrow{R} S(k, m_i, n_i)$.

## Construction

### Construction from PRF

> [!algorithm] MAC Construction from PRF
> For a PRF $F$ define over $(\mathcal K, \mathcal X, \mathcal Y)$, we define the **deterministic MAC system $\mathcal I = (S, V)$ derived from $F$** as:
> - $S(k, m) = F(k, m)$;
> - $V(k, m, t) = \begin{cases}\text{accept} &\text{if } F(k, m) = t, \\ \text{reject} &\text{otherwise}\end{cases}$

> [!theorem]
> Let $F$ be a secure PRF defined over $(\mathcal K, \mathcal X, \mathcal Y)$, where $|\mathcal Y|$ is super-poly. Then the deterministic MAC system $\mathcal I$ derived from $F$ is a secure MAC.
> 
> In particular, for every $Q$-query [[#MAC Security|MAC security]] adversary $\mathcal A$ that attacks $\mathcal I$, there exists a $(Q + 1)$-query [[Pseudorandom Function#Definition|secure PRF]] adversary $\mathcal B$ that attacks $F$, where $\mathcal B$ is an elementary wrapper around $\mathcal A$, such that $$\text{MACadv}[\mathcal A, \mathcal I] \leq \text{PRFadv}[\mathcal B, F] + 1/|\mathcal Y|$$

### Construction from PRF, UHF Composition

> [!algorithm] PRF, UHF Composition
> Let $H$ be a keyed hash function defined over $(\mathcal K_H, \mathcal M, \mathcal X)$ and let $F$ be a PRF defined over $(\mathcal K_F, \mathcal X, \mathcal T)$. As usual, we assume $\mathcal M$ contains much longer messages than $\mathcal X$, so that $H$ hashes long inputs to short digests. We build a new PRF, denoted $F'$, by composing the hash function $H$ with the PRF $F$. More precisely, $F'$ is defined as follows: $$F'((k_1, k_2), m) = F(k_2, H(k_1, m))$$
> We refer to $F'$ as the **composition of $F$ and $H$**. It takes inputs in $\mathcal M$ and outputs value in $\mathcal T$ using a key $(k_1, k_2)$ in $\mathcal K_H \times \mathcal K_F$. Thus, we obtain a PRF with the same output space as the underlying $F$, but taking much longer inputs.

> [!theorem] PRF (UHF Composition)
> Suppose $H$ is a computational UHF and $F$ is a secure PRF. Then $F'$ is a secure PRF.
> 
> In particular, suppose $\mathcal A$ is a [[Pseudorandom Function#Definition|secure PRF]] adversary with respect to $F'$ and issues at most $Q$ queries. Then there exist a [[Pseudorandom Function#Definition|secure PRF]] adversary $\mathcal B_F$ and a [[Hash Function#Secure Universal Hash Function|secure UHF]] adversary $\mathcal B_H$, $$\text{PRFadv}[\mathcal A, F'] \leq \text{PRFadv}[\mathcal B_F, F] + (Q^2/2) \cdot \text{UHFadv}[\mathcal B_H, H].$$
> More generally, there exists a $Q$-query [[Hash Function#Multi-query Universal Hash Function|secure multi-query UHF]] adversary $\mathcal B_H'$, which is an elementary wrapper around $\mathcal A$ such that $$\text{PRFadv}[\mathcal A, F'] \leq \text{PRFadv}[\mathcal B_F, F] + \text{MUHFadv}[\mathcal B_H', H].$$

### Carter-Wegman MAC

> [!algorithm] Carter-Wegman MAC
> Fix some large integer $N$ and set $\mathcal T = \mathbb Z_N$, the group of size $N$ where addition is defined "modulo $N$." We use a hash function $H$ and a PRF $F$ that output values in $\mathbb Z_N$:
> - $H$ is a keyed hash function defined over $(\mathcal K_H, \mathcal M, \mathcal T)$,
> - $F$ is a PRF defined over $(\mathcal K_F, \mathcal R, \mathcal T)$.
> 
> The Carter-Wegman MAC, denoted $\mathcal I_{CW}$, takes inputs in $\mathcal M$ and outputs tags in $\mathcal R \times \mathcal T$. It uses keys in $\mathcal K_H \times \mathcal K_F$. The **Carter-Wegman MAC derived from $F$ and $H$** works as follows:
> - For key $(k_1, k_2)$ and message $m$ we define
> 
> $S((k_1, k_2), m)$
> 1. $r \xleftarrow{R} \mathcal R$
> 2. $v \leftarrow H(k_1, m) + F(k_2, r) \in \mathbb Z_N$
> 3. Output $(r, v)$
> - For key $(k_1, k_2)$, message $m$, and tag $(r, v)$, we define
> 
> $V((k_1, k_2), m, (r, v))$
> 1. $v^* \leftarrow H(k_1, m) + F(k_2, r) \in \mathbb Z_N$
> 2. If $v = v^*$ output `accept`; otherwise output `reject`.

> [!algorithm] Encrypted UHF MAC
> The Carter-Wegman MAC can be described as an encryption of the output of a hash function. Indeed, let $\mathcal E = (E, D)$ be the cipher $$E(k, m) = \{r \xleftarrow{R} \mathcal R, \text{output} (r, m + F(k, r))\} \quad \text{and} \quad D(k, (r, c)) = c - F(k, r)$$
> where $F$ is a PRF defined over $(\mathcal K_F, \mathcal R, \mathcal T)$. This cipher is CPA secure when $F$ is a secure PRF. Then the Carter-Wegman MAC can be written as:
> $S((k_1, k_2), m) = E(k_2, H(k_1, m))$
> $V((k_1, k_2), m, t) = \begin{cases}\text{accept}&\text{if } D(k_2, t) = H(k_1, m),\\ \text{reject}&\text{otherwise}\end{cases}$ 
> which we call the **encrypted UHF MAC system derived from $\mathcal E$ and $H$**.

> [!theorem] Carter-Wegman Security
> Let $F$ be a secure PRF defined over $(\mathcal K_F, \mathcal R, \mathcal T)$ where $|\mathcal R|$ is super-poly. Let $H$ be a computational DUF defined over $(\mathcal K_H, \mathcal M, \mathcal T)$. Then the Carter-Wegman MAC $\mathcal I_{CW}$ derived from $F$ and $H$ is a secure MAC.
> 
> In particular, for every [[#MAC Security|MAC security]] adversary $\mathcal A$ that attacks $\mathcal I_{CW}$, there exist a [[Pseudorandom Function#Definition|secure PRF]] adversary $\mathcal B_F$ and a [[Hash Function#Difference Unpredictability|DUF]] adversary $\mathcal B_H$, which are elementary wrappers around $\mathcal A$, such that $$\text{MACadv}[\mathcal A, \mathcal I_{CW}] \leq \text{PRFadv}[\mathcal B_F, F] + \text{DUFadv}[\mathcal B_H, H] + \frac{Q^2}{2|\mathcal R|} + \frac{1}{|\mathcal T|}$$

### Construction from Collision Resistant Hash

> [!algorithm] Collision Resistant Hash
> Let $H$ be a hash function that hashes long messages in $\mathcal M$ to short digests in $\mathcal T_H$. Suppose $\mathcal I$ is defined over $(\mathcal K, \mathcal T_H, \mathcal T)$. Define $\mathcal I' = (S', V')$ for long messages as follows:
> $$S'(k, m) = S(k, H(m)), \text{ and } V'(k, m, t) = V(k, H(m), t)$$
> Then $\mathcal I'$ authenticates long messages in $\mathcal M$.

> [!theorem]
> Suppose the MAC system $\mathcal I$ is a secure MAC and the hash function $H$ is collision resistant. Then the derived MAC system $\mathcal I' = (S', V')$ is a secure MAC.
> In particular, suppose $\mathcal A$ is a [[#MAC Security|MAC security]] adversary attacking $\mathcal I'$. Then there exist a [[#MAC Security|MAC security]] adversary $\mathcal B_{\mathcal I}$ and an efficient [[Hash Function#Definition|collision finder]] $\mathcal B_H$, which are elementary wrappers around $\mathcal A$ such that $$\text{MACadv}[\mathcal A, \mathcal I'] \leq \text{MACadv}[\mathcal B_{\mathcal I}, \mathcal I] + \text{CRadv}[\mathcal B_H, H].$$

> [!algorithm] Nonce-based Carter-Wegman MAC

> $S((k_1, k_2), m, n) = H(k_1, m) + F(k_2, n)$
> $V((k_1, k_2), m, t, n) = \begin{cases}\text{accept}&\text{if } t = S((k_1, k_2), m, n) \\ \text{reject} &\text{otherwise}\end{cases}$

> [!theorem]
> $\text{nMACadv}[\mathcal A, \mathcal I_{CW}] \leq \text{PRFadv}[\mathcal B_F, F] + \text{DUFadv}[\mathcal B_H, H] + \frac{1}{|\mathcal T|}.$

### PMAC: A parallel MAC

> [!algorithm] PMAC
> Let $F_1$ be a PRF defined over $(\mathcal K_1, \mathbb Z_p, \mathcal Y)$, where $p$ is a prime and $\mathcal Y = \{0, 1\}^n$. Let $F_2$ be a PRF defined over $(\mathcal K_2, \mathcal Y, \mathcal Z)$. The $\text{PMAC}_0$ construction works as follows:
> 
> ---
> **Input**: $m = (a_1, \dots, a_v) \in \mathbb Z_p^v$ for some $0 \leq v \leq \ell$, and key $\vec{k} = (k, k_1, k_2)$ where $k \in \mathbb Z_p, k_1 \in \mathcal K_1$, and $k_2 \in \mathcal K_2$
> **Output**: Tag in $\mathcal Z$
> $\text{PMAC}_0(\vec{k}, m)$:
> 1. $t \leftarrow 0^n \in \mathcal Y, \quad mask \leftarrow 0 \in \mathbb Z_p$
> 2. For $i \leftarrow 1$ to $v$ do:
> 	1. $mask \leftarrow mask + k$
> 	2. $r \leftarrow a_i + mask$
> 	3. $t \leftarrow t \oplus F_1(k_1, r)$
> 3. Output $F_2(k_2, t)$

> [!theorem]
> If $F_1$ and $F_2$ are [[Pseudorandom Function#Definition|secure PRF]], and $|\mathcal Y|$ and the prime $p$ are super-poly, then $\text{PMAC}_0$ is a [[Pseudorandom Function#Definition|secure PRF]] for any poly-bounded $\ell$.
> 
> In particular, for every [[Pseudorandom Function#Definition|secure PRF]] adversary $\mathcal A$ that attacks $\text{PMAC}_0$, and issues at most $Q$ queries, there exist [[Pseudorandom Function#Definition|secure PRF]] adversaries $\mathcal B_1$ and $\mathcal B_2$, which are elementary wrappers around $\mathcal A$, such that $$\text{PRFadv}[\mathcal A, \text{PMAC}_0] \leq \text{PRFadv}[\mathcal B_1, F_1] + \text{PRFadv}[\mathcal B_2, F_2] + \frac{Q^2}{2|\mathcal Y|} + \frac{Q^2 \ell^2}{2p}.$$
